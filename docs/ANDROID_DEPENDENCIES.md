The F-Droid path uses `npm ci --omit=optional`, so npm's platform-specific `@esbuild/*` executable packages are not installed. `scripts/build-esbuild-from-source.sh` compiles the pinned esbuild source with the pinned `golang.org/x/sys` source, disables Go module network access, and checks the generated CLI version. The F-Droid asset build requires this executable through `NEXUS_ESBUILD_BINARY`; ordinary local/Play builds can continue to use the npm wrapper.

GitHub Actions exercises the source-build path. This is not yet evidence that F-Droid's isolated buildserver recipe succeeds; the fdroiddata source-library metadata and buildserver run remain outstanding.

## Gradle dependency verification

`android/gradle/verification-metadata.xml` pins SHA-256 checksums for Gradle artifacts and metadata. The file has `verify-metadata=true`, so POM and Gradle module metadata are covered as well as binary artifacts.

The Android CI workflow now applies `--dependency-verification strict` to both F-Droid runtime dependency reports and all requested APK/AAB build tasks. CI is read-only: it does not run `--write-verification-metadata`, mutate the committed verification file, or push checksum changes. Dependency updates must be reviewed and committed deliberately. A final `git diff --exit-code` check rejects any generated change.

The latest strict build identified three metadata entries that were missing from the committed set. They were cross-checked against independent public verification records before being added:

- `com.google.guava:guava-parent:33.3.1-jre`, `guava-parent-33.3.1-jre.pom`: SHA-256 `55441db27e8869dfefe053059bdf478bdc7e95585642bf391f0023345fd56287`. Corroborating records: [Cloudsmith package checksum](https://cloudsmith.io/~scandit/repos/maven/packages/detail/maven/guava-parent/33.3.1-jre/a%3Dnoarch%3Bxg%3Dcom.google.guava/) and [SonarSource Gradle verification metadata](https://github.com/SonarSource/sonar-kotlin/blob/076f5d2b89a7a512f0dda6ce3f44062938455733/gradle/verification-metadata.xml).
- `org.junit:junit-bom:5.10.2`, `junit-bom-5.10.2.module`: SHA-256 `de23b114b3e4119a8fe6eb17bed5a3852816698bace67071579d6d927ebb080a`. Corroborating record: [Microsoft SEAL Gradle verification metadata](https://github.com/microsoft/SEAL/blob/ce53aa40969364f79599009bc8882f71fce0c13d/android/gradle/verification-metadata.xml), which records this value as verified against Maven Central SHA-1.
- `org.jetbrains.kotlinx:kotlinx-coroutines-bom:1.8.0`, `kotlinx-coroutines-bom-1.8.0.pom`: SHA-256 `1239e9dbe1397cd5971342956b2511bc3ace7b641842e4372a088dcfa8b9ad55`. Corroborating records: [Apache Airflow](https://github.com/apache/airflow/blob/e10575d5479312ef050d984d06f4e048a6b73128/java-sdk/gradle/verification-metadata.xml) and [Apache JMeter](https://github.com/apache/jmeter/blob/ba2e9ba15a73ddac44e8ef28e3dbdf4d155b5f3c/gradle/verification-metadata.xml) verification manifests, plus independent Gradle lockfile records.

These cross-checks corroborate the three added values; they are not a substitute for PGP signature verification. The remaining entries marked `Generated by Gradle` are trust-on-first-use checksums, not independently authenticated upstream identities. `verify-signatures=false` remains in effect, so Gradle signature verification is not enabled. Continue reviewing upstream checksums/signatures wherever available before an F-Droid submission.

Strict Gradle dependency verification now passes through the F-Droid runtime dependency reports and dependency resolution. The first release build then reached Android's `lintVitalAnalyzeFdroidRelease` task and failed because the temporary `.build/esbuild` source checkout was copied into the packaged web-assets directory. The static build now excludes `.build`, and the Android test suite asserts that no build-tool checkout enters `dist` or the Android assets.

## Generated npm dependency inventory

After the F-Droid npm installation, CI runs `npm run android:sbom` and uploads `android/build/reports/third-party/npm-dependencies.json` plus the corresponding Markdown report. The inventory is tied to the reconstructed npm lockfile SHA-256 and source commit, and records resolved URLs, integrity values, package licences, licence-file presence and provenance links. The existing Android static test requires this report to cover the full installed dependency tree. Missing or non-allow-listed declared licences continue to fail the static audit. This does not yet complete the separate Gradle/Maven licence and binary audit, nor prove that each package's declared licence is legally correct.
