## F-Droid build-only source dependencies

| Dependency | Purpose | Pinned source | Licence |
|---|---|---|---|
| esbuild 0.28.2 | Android bridge bundler; build-only | `evanw/esbuild` commit `609683d892977362a0f99026cb74b96263d728a9` | MIT |
| `golang.org/x/sys` | Go source dependency used to compile esbuild; build-only | `golang/sys` commit `c0bba94af5f85fbad9f6dc2e04ed5b8fac9696cf` | BSD-3-Clause |

The F-Droid path uses `npm ci --omit=optional`, so npm's platform-specific `@esbuild/*` executable packages are not installed. `scripts/build-esbuild-from-source.sh` compiles the pinned esbuild source with the pinned `golang.org/x/sys` source, disables Go module network access, and checks the generated CLI version. The F-Droid asset build requires this executable through `NEXUS_ESBUILD_BINARY`; ordinary local/Play builds can continue to use the npm wrapper.

GitHub Actions exercises the source-build path. This is not yet evidence that F-Droid's isolated buildserver recipe succeeds; the fdroiddata source-library metadata and buildserver run remain outstanding.

## Gradle dependency verification

`android/gradle/verification-metadata.xml` pins SHA-256 checksums for Gradle artifacts resolved by CI, and the Android workflow uses `--dependency-verification strict`. The initial values have `origin="Generated by Gradle"`: this is a trust-on-first-use baseline that protects later builds from unexpected artifact changes, not independent authentication of the original upstream artifacts. Existing hashes are protected against silent regeneration; new entries are added only after the workflow checks that no existing hash changed.

The metadata contains build-time as well as runtime Gradle/Maven components. A complete upstream checksum/signature and licence review for the resolved Gradle/Maven graph is still required before F-Droid submission.
